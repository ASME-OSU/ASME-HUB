# V02 — Private actual Form destination check

This standalone Apps Script runs manually under each officer's Google authorization. All officers remain eligible through their own Google access. The Hub phrase, roles, public URLs, and local checkmarks grant no access. This source is implemented and tested locally; it has **not been installed or run against the annual Google Form**. V02 remains unverified until the live check is performed.

The script reads the actual Form `linkedSheetId` using the Google Forms API, then reads only the intended workbook's `spreadsheetId` using the Sheets API. It makes two fixed-host GET requests at most. It does not read responses, questions, roster, names, emails, or cell data; it does not copy files, submit data, link destinations, change settings, or activate a year. No endpoint or trigger is needed. Do not deploy it as a web app or add it to the public Hub bundle.

## One-time private setup

1. Sign in to the Google account that will perform the officer's check. Open the annual Form **editor** and the intended private annual Points Master. Confirm the resources and academic year from the private annual registry. The input year labels this evidence; the script does not determine which annual workbook is correct. The workbook's title is not an identity check.
2. Create a separate standalone Apps Script project at [Apps Script](https://script.google.com/) in ASME-controlled private storage. Name it `ASME Form Destination Check — Private`. Do not bind it to the anyone-reader Control Center or publish it. Limit project access to authorized officers; project editors can view the configured private IDs. Keep continuity instructions and the project reference in the private handoff record.
3. Copy [FormDestinationValidator.gs.example](FormDestinationValidator.gs.example) into a `.gs` file. In Project Settings enable **Show appsscript.json manifest file in editor**. Copy [the manifest example](FormDestinationValidator.appsscript.json.example) into `appsscript.json`. Keep exactly the three listed scopes: Forms body read-only, Sheets read-only, and external requests. No Drive/response/write scope is required.
4. Use a dedicated standard Google Cloud project for this new script so API enablement can be managed. In Apps Script Project Settings → Google Cloud Project → Change project, enter its **project number**. In that Cloud project's APIs & Services library enable **Google Forms API** and **Google Sheets API**. Configure its Google Auth/OAuth consent for the officer accounts (internal where available, or external testing with those users added). Apps Script manages the OAuth token; do not create or paste a client secret or password. If an administrator blocks consent/API access, record Unable to verify and use the manual Google editor route. Do not expand scopes to bypass a policy block.
5. In the private script's `input`, set `yearKey` to a consecutive annual key such as `2027-2028`, `form` to the editor ID or `https://docs.google.com/forms/d/ID/edit`, and `pointsMaster` to its ID or `https://docs.google.com/spreadsheets/d/ID/edit`. An ID has 10–200 letters, numbers, underscores or hyphens. Use the editor address for the Form: `/forms/d/e/.../viewform`, `forms.gle`, prefilled/respondent links, and published `1FAIpQL...` IDs are rejected. There is no supported conversion from published ID to editable ID here. Open the Form from Drive/editor if necessary. Do not paste these private values into the public repository, Hub, or logs.

Creating a script and enabling APIs are setup changes an authorized owner performs separately; none were performed by this implementation. Reuse this private project once established. Never change an existing production script's Cloud project to install this checker. Configure access continuity for the script and its Cloud project before outgoing officers leave; each incoming officer must still perform their own authorized run.

## Run and inspect the result

1. Save the private script. Select `runFormDestinationCheck` in the editor's function dropdown and choose **Run** once to complete Google's consent prompts. A successful run logs only a generic status, reason code, and check time. A return value is **not** automatically displayed by Run. Consent/setup failure before execution produces no result and is Unable to verify, never Passed.
2. To inspect evidence, click the line-number gutter on **`return result;` inside `runFormDestinationCheck`** to add a breakpoint. Choose **Debug** with that function selected. When paused, expand `result` in the debugger's Variables panel. Record its fields in the restricted annual Transition Evidence record; expand and copy each displayed value as needed. Do **not** add `console.log(result)`, log OAuth tokens, copy all debugger locals, or share screenshots with private IDs. Resume/stop debugging when done. This reruns fresh reads; use the result from this Debug run, not the earlier generic log.
3. Confirm the configured year, actual editor Form ID and intended annual workbook ID against the private registry. For a match, record the observed destination ID too. `checkedAt` is UTC at check start; `checkVersion` is 1 and `method` is `authorized-google-rest`. Record the authorized officer/method privately and note that these are consecutive reads, not an atomic snapshot. The script stores no evidence automatically.
4. Also inspect Google Forms → Responses → linked spreadsheet and the actual response **tab**, and reconcile `response_sheet_name`/formula references. This checker compares workbook identity only. It does not prove tab/schema, response delivery, scripts/triggers, processing, edit permission, or public suppression. V03–V05 are separate checks and no synthetic submission is part of this slice.

Only mark V02 manually confirmed in the wizard after private live evidence matches the current resources and the manual workbook/tab inspection succeeds. Keep private IDs out of wizard notes and exported progress. The checker has no connection that automatically passes or imports V02; local mocked tests and an entered URL never establish linkage.

## Outcomes and next actions

| Script status | Verification status | Meaning / next action |
| --- | --- | --- |
| `match` | Passed for workbook identity at check time | Google returned the actual destination equal to the accessible intended workbook. Complete tab inspection and retain private evidence. This does not activate the year. |
| `mismatch` | Failed | Google returned another workbook. Stop submissions. Privately inspect both references; an authorized officer must correct the annual Form's Responses destination in Google, then rerun V02. The checker never repairs it. |
| `unlinked` | Failed | Google returned no linked spreadsheet and the intended workbook was accessible. Select the intended destination separately in Google, then rerun. |
| `inaccessible` | Unable to verify | A Form/workbook read failed, including unauthorized, forbidden, not found, disabled API, quota/network/service failure. No inference about linkage. Check account, effective file access, API enablement/consent and retry; don't make files public. |
| `invalid` | Not checked / Unable to verify | Invalid year/ID/editor URL prevents all reads; a malformed Google response or inconsistent returned identity prevents confirmation. Correct input or investigate/retry. Error bodies and values are not logged. |

If the Form read succeeds but the intended workbook is unavailable, status remains inaccessible even if a destination was observed; private evidence may retain that observed ID. A mismatch needs no access to the other destination workbook and does not open it.

## Freshness and private evidence

Keep check ID/version, method, UTC time, year key, Form ID, intended workbook ID, observed destination ID (or none), status/reason, officer and evidence location together in a restricted record. Invalid inputs return no raw IDs. Results are point-in-time and not signed certificates; local copies can be edited. Reject evidence for another year/Form/workbook, a changed destination, old checker version, or changed relevant access/configuration. Mark V02 **Needs recheck** and run again after either resource changes, relinking/unlinking, a copy, or a conflicting officer edit, and immediately before readiness review/activation. The Form revision ID is not used as a destination freshness guarantee. After remediation repeat dependent delivery/processing checks separately under S10 authorization.
