## Installed standalone Google project

The installed project bundles several generic sources into larger files. This
map describes the October 3, 2026 installation; compare actual installed source
and deployment versions against private evidence before changing it.

| Installed file | Purpose |
|---|---|
| `Code.gs` | AnnualCopyEngine and runner/adapter; optional reviewed creation/resume with copy journals, plus historical fixture helpers |
| `AnnualSetupV2.gs` | AnnualSetupEngine/runner and AnnualSettingsDraftEngine/runner; optional workbook/Form configuration and shared inactive append/readback logic |
| `AnnualSettingsWeb.gs` | ManualAnnualVerificationEngine/runner and AnnualSettingsWebApp; chapter authentication, trusted rules, resource verification and expiring reviewed save |
| `AnnualSettingsPage.html` | Google-hosted import/Verify/review/Save interface |
| `appsscript.json` | Drive/Sheets/Forms/email scopes, Drive v3 service, runtime/timezone and self-only accessing-user deployment settings |
| `SourceMetadataProbe.gs`, `SourceContentProbe.gs` | Read-only development evidence of source ownership, parent/version, headers, formulas and configuration |
| `AnnualV2RehearsalConfig.gs` | Private automated-copy fixture configuration |
| `AnnualV2CopyExecution.gs` | Explicit fixture copy/repeat actions |
| `AnnualV2SetupExecution.gs` | Explicit fixture Form/workbook setup actions |
| `AnnualV2SettingsExecution.gs` | Fixture inactive append/readback/repeat actions |
| `AnnualV2LiveStep.gs` | Editor launch helper currently calling `repeatAnnualV2Settings()` for a private fixture |
| `ManualAnnualLiveReview.gs` | Maintainer source review, manual-copy fixture save/repeat, snapshot diagnostic and production-rule provisioning |

Officers use the authenticated page in **manual-copy mode**. Probe, fixture and
provisioning functions are private maintainer tools, not normal officer steps.
The annual workflow has no newly installed background trigger; its actions are
explicit. Existing bound workbook scripts/triggers require separate review.

## Generic repository examples

The [annual save instructions](../../integrations/apps-script/ANNUAL_SETTINGS_DRAFT.md)
describe how the `.gs.example` files map into the private project. Do not paste
every example into it indiscriminately:

- `Code.gs.example` is an optional aggregate dashboard-feed starter, **not** the
  installed copy engine's `Code.gs`. Its entry point must not collide with the
  annual web app.
- `SettingsWriter.gs.example` is a disabled legacy writer. Its presence/removal
  does not establish whether any old external deployment was retired.
- `FormDestinationValidator.gs.example` is a separate read-only helper. The
  annual verifier also checks the actual destination directly.
- Annual engines implement validation/plans. Runners/adapters connect them to
  actual Google services, locks, private properties and ledgers.

GitHub stores generic code and contracts. Installed source snapshots, project
identifiers, trusted rules, approval records and ledgers stay in private Drive.
Pushing GitHub code does not deploy Google Apps Script.
