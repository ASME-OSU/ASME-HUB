# Private annual handoff checklist

Copy this empty template into the chapter-controlled handoff folder for the intended year. The President coordinates the handoff. **Real handoff** is the normal route; choose **Practice (maintainer review)** only for an agreed separate exercise. This template records actual observations and decisions; it is not an executed result.

A staged Form can be closed or unpublished as intended. Record that state honestly. Before collecting attendance, the authorized operator verifies the approved publication, respondent access and intake state; incoming officers do not publish ad hoc to remove a blocker.

Use **Not checked**, **In progress**, **Blocked** or **Complete**, with the actual observer, time, evidence and next action. Historical practice results do not complete a real handoff observation. Missing technical evidence is a maintainer task; incoming officers do not need to generate fictional submissions or financial inputs to start this checklist.

## T01 Confirm access and materials

- [ ] Get the current handoff folder and checklist from the President.
- [ ] Open required tools using each incoming holder's own account.
- [ ] Record missing view/edit access and ask the President to arrange it.

## T02 Get this year's tools

- [ ] Open the existing annual bundle supplied by the President or maintainer.
- [ ] Compare year and file identities with the actual setup receipt.
- [ ] Record maintainer confirmation of response wiring, import sources, dates, intended inactive settings and event-update method/owner. Repository source does not prove native installation.

## T03 Prepare attendance and finances

- [ ] Points officer reviews intended attendance operation, member results and unresolved exceptions.
- [ ] Maintainer supplies dated technical readiness evidence, including configured response-tab scope and relevant installed automation.
- [ ] Treasurer reviews real approved funding, balances, pending transactions and bank reconciliation.
- [ ] Assign any unresolved technical or financial work. Agree a controlled verification plan if existing evidence is insufficient.

## T04 Update calendars and communications

- [ ] Confirm calendar/newsletter owners, approved sources and upcoming dates.
- [ ] Prepare communications with reviewed facts, sender details and approval.
- [ ] Keep separate backups of Hub progress, private links and editable Newsletter Draft. Reference the maintainer's recovery evidence and any unresolved restore work.

## T05 Approve and switch to the new year

- [ ] Record incoming acceptance, remaining blockers and their owners.
- [ ] Record the President's handoff decision and separate launch approval.
- [ ] Authorized operator records any approved switch, readback and rollback plan. An inactive saved row alone is not activation.
- [ ] Agree outgoing access changes after incoming acceptance.

## Optional maintainer practice

If a separate practice is agreed, record its approved account, private copies, operator, purpose and reviewer. The maintainer chooses scenarios appropriate to the uncertainty: for example attendance delivery/scoring, fictional budget arithmetic, calendar previews or three-file recovery. The documented five-case scenario is one possible practice plan, not a requirement for every officer or real handoff.

Before adding fictional inputs, inventory existing retained evidence and decide whether to inspect it or run new controlled tests. Record actual results, limits and keep/remove decisions in the [selective practice cleanup record](selective-mock-cleanup-template.md). Practice acceptance never supplies real incoming-account access, funding approval or launch authority.
