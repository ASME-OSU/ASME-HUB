It creates an attempt only if none matches. More options contains the explicit separate-attempt action and genuine saved alternatives; in-memory placeholders are not listed as saved. ### Note drafts

Leaving or reloading also warns while connected Annual Setup is pending,
including sign-in, workspace loading and annual-file requests. This warning does
not cancel Google server work. If a request is interrupted, preserve its year
and workspace and reconcile the same run before retrying.

Service-worker updates never reload the page automatically. After a controlled
page receives a replacement worker, an update notice appears below the dashboard
topbar. Finish the current work and save drafts before choosing **Reload Hub**.
The notice remains available if the browser's leave/reload warning is canceled.
An active modal can be finished and closed before using the notice.

Evidence drafts stay in memory by year, attempt and review while controls redraw or officers navigate. Save note commits one draft; completing a step or finishing the handoff/practice also commits drafts for that attempt through the existing concurrency guard. Reloading/leaving with unsaved drafts prompts the browser warning. Drafts do not enter exports until saved. A draft based on evidence changed in another tab cannot overwrite that evidence after reload; copy the draft, discard it and reconcile against the saved version.

Private-link field drafts follow the same in-memory isolation by year and attempt, including imported links awaiting review. Switching checklists restores their pending fields; saving commits the link list and clears its draft. Discard link edits reloads the saved list. Preserved drafts retain their original saved-data baseline so loading newer storage cannot make stale edits eligible to overwrite it. Leaving warns for pending drafts in any checklist. Progress export and printing stop for pending notes in the selected checklist; private-link export stops for pending link edits. Each action explains how to save or discard the relevant edits.


## Chapter sign-in and Practice workspace recovery

If Step 2 reports that the workspace purpose does not match, Google sign-in has succeeded. Continue a separate Practice checklist for a Practice workspace. A Real handoff requires a separately approved Real handoff workspace; signing in again does not change the saved workspace purpose.

If an existing run stops at a chapter-ownership or private-file check, inspect the configured Control Center and annual workspace folder in Drive. A file in Trash can produce these older errors even when the chapter owns it. Restore the same approved Practice resources, then reopen the same year. Preserve the existing receipt and file IDs; do not replace the workspace merely to clear an error. Keep ownership and privacy checks enabled.

The browser recovery fixes and the clearer Apps Script Trash errors have separate release steps: publish the Hub assets, and install/version the reviewed provisioner source in the chapter-owned API deployment. A repository merge alone does not update Apps Script.

### Waiting for connected setup

Google sign-in waits for the popup for up to two minutes. If Google never returns an answer, close the old popup, allow popups for the Hub and sign in again. Late answers from an expired attempt cannot replace a newer sign-in. After authorization, the Hub separately reports workspace loading and annual-file creation; a longer wait displays same-year recovery guidance. Google setup can continue after a browser connection fails. Preserve the selected year, workspace and existing receipt when reopening; a client timeout does not prove that Google stopped or that no files were created.
